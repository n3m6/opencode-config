### Authoring or modifying a skill

Own the skill's voice and its observable behavior.

1. Use the available skill-creator to author or revise the requested skill. Preserve user scope, supported metadata, and existing invocation policy.
2. Validate frontmatter, referenced files, cross-skill links, and actual helper behavior. Move conditional detail into references when that makes the entry point easier to use.
3. Exercise representative requests when the change affects routing, tool choices, or substantive behavior. Use isolated fixtures and independent agents only when available and authorized. Report when activation or independent testing was not exercised.
4. Deliver the artifact and validation. Use Opening a PR only when PR delivery is part of the task.

Keep instructions that change a decision. Prefer a structural enforcement mechanism when the lesson can be expressed as a type, lint, check, or deterministic helper.

**Reply:** the skill, substantive choices, validation, and remaining gaps.
